# 단계별 학습 계획 검토

2026-11-27, 1kg 물체·CPU MuJoCo·105차원 관측·14차원 행동 기준.

업데이트: 새 PPO·A2C·SAC 실행에는 아래 1단계의 가까운 초기 자세·새 보상·모델별 독립 난이도 승급을 `simulation/study_curriculum.py`로 연결했다. 아래의 기존 코드 진단은 이전 모드에 대한 검토 기록이다. 후속 전달 시나리오의 완주 검증은 여전히 남아 있다.

현재 학습 프로세스는 유지한 채 소스와 별도 물리 환경을 점검했다. 아래의 IK 제어기는 물리적 가능성을 확인하기 위한 시험용이다. 학습 정책에 추가하지 않았으며, 이 시험의 성공은 PPO 수렴이나 모든 랜덤 배치의 해결 가능성을 뜻하지 않는다.

## 확인한 결과

| 항목 | 결과 | 해석 |
|---|---|---|
| 기존 관련 회귀 테스트 | 30개 통과 | 커리큘럼·실제 잡기 초기화·체크포인트 전달·랜덤 초기화·스케줄의 기존 동작 확인 |
| 1kg 잡기·들기 | 물리적 성공 사례 확인 | 기존 테스트는 좌우 팔을 각각 확인한다. 별도 접근 시험에서도 열린 집게로 접근해 들기에 성공했다. |
| 가까운 시작 자세 | 물체 중심에서 약 5.0cm·7.8cm 떨어진 열린 집게로 시작해 성공한 사례 확인 | 초기 관절 제한과 충돌을 확인한 사례다. 현재 random_approach 초기화 조건을 그대로 쓰면 이 거리에서는 시작할 수 없다. |
| 한 팔 운반·놓기 | 시작/목표 중심 거리 약 25.0·45.0·50.1·59.1cm에서 성공 사례 확인 | 최종 중심 오차 약 1.1·1.7·1.4·1.8cm. 실제 접촉·중력·모터 제한을 사용했다. |
| 양팔 전달 자세 | 물체 중심의 x방향 ±5.5cm, 높이 82cm인 양팔 자세 3개 확인 | y=-20·0·20cm에서 관절 범위 내 충돌 없는 자세를 찾았다. 물체를 실제로 넘겼다는 뜻은 아니다. |
| 실제 양팔 전달 | 아직 성공을 확인하지 못함 | 별도 시험에서 왼팔로 들어 중앙 근처까지 옮겼으나 오른팔의 안정적인 잡기에 실패했다. 다른 시작 자세 하나는 시험용 초기 자세 생성에 실패했다. 전달 불가능의 증명은 아니다. |

물체는 실행 시 길이 18cm, 무게 1kg이다. XML 원본의 물체 길이와 실행 중 크기는 다르므로 실행 중 모델 값을 기준으로 확인했다.

시험용 IK는 일부 시작 자세에서 대기 중인 팔의 해가 제어 가능한 회전 범위를 벗어났다. 이런 초기화 실패를 곧바로 물리적 도달 불가로 판정하지 않았다. 도달 가능한 위치라도 IK 해의 선택·물체 기울기·접근 경로에 따라 실패했으므로, 단일 제어기의 성공률을 환경 자체의 해결 가능 비율로 사용하지 않는다.

## 현재 코드에서 계획과 다른 부분

1. **1단계 최저 난이도가 이미 멀다.** `simulation/arm_initialization.py`는 두 손 모두 물체와 최소 15cm 떨어지도록 하고, 집게 높이도 최소 78cm로 제한한다. 테이블 위 물체 중심은 약 62.7cm여서 높이 차이만 약 15.3cm다. 5~10cm 시작을 만들려면 두 조건을 함께 수정해야 한다. 높이 제한만 낮추면서 충돌 검사를 빼면 안 된다.
2. **랜덤 1·2단계의 출발/도착 분포는 난이도와 무관하다.** `solo_layout`·`solo_goal`은 난이도를 읽지 않는다. 같은 시드 12개로 난이도 0과 1을 비교했더니 모든 시작/목표 거리가 동일했다. 약 26.5~54.6cm였고, 쉬운 운반부터 시작한다는 보장은 없다.
3. **랜덤 3단계도 아직 시나리오 교육과정이 아니다.** `full_layout`은 시작과 목표에 각각 어느 팔 하나가 닿는지를 검사한다. 장애물 회피 경로, 두 팔의 공유 작업 공간, 물체가 끼지 않는 전달 경로는 검증하지 않는다. 도달 검사 내부에서는 장애물을 숨기므로 실제 장애물과 팔의 간섭을 해결 가능성 검사로 볼 수도 없다.
4. **스텝 예산 전환과 성공률 승급이 별개다.** `StageHandoff.due`는 단계와 스텝만 확인한다. 현재 실행의 2천만 스텝 전환은 1단계가 실패 중이어도 발생한다. 2단계는 실제로 성공한 1단계 잡기로 초기 상태를 만들기 때문에, 잡기 모델이 약하면 초기화 재시도가 소진되어 실행이 실패할 수 있다.
5. **1kg이라는 조건이 양팔 협동을 필수로 만들지는 않는다.** 한 팔로 잡고 운반하는 성공 사례가 이미 있다. 전달이 필요한 배치는 도달 범위로 구성하고, 동시에 두 팔로 지탱하는 배치는 실제 동역학 시험을 먼저 통과해야 한다. 모든 배치에서 협동을 강제하지 않는다.

## 보완한 학습 순서

### 1단계: 접근·잡기·들기

모든 난이도에서 물체는 테이블 위, 집게는 열린 상태로 시작한다. 성공 조건은 실제 잡기로 물체 바닥을 테이블보다 3cm 이상 올리고, 들고 있는 상태를 0.5초 유지하는 것이다.

| 난이도 | 초기 집게 중심~물체 중심 거리 | 추가 변화 |
|---|---|---|
| 0 | 5~10cm | 한 팔 작업 영역 일부, 잡기 방향이 정렬된 자세 주변에서 작은 무작위 변동 |
| 1 | 10~20cm | 출발 위치와 접근 방향 범위를 조금 확대 |
| 2 | 20~35cm | 해당 팔의 작업 영역을 확대하고 관절 자세 변화도 확대 |
| 3 | 35~50cm | 여러 접근 방향과 더 큰 자세 변화 |
| 4 | 50cm 이상, 검증된 안전 범위 | 물체 좌표를 IK 목표로 삼지 않는 임의 관절 자세로 확장 |

앞서 제안한 최종 50~70cm 범위의 상한은 확정하지 않는다. 랜덤 자세의 충돌·관절 제한·실제 접근 동작을 검증한 후 정한다. 거리와 자세를 한 번에 크게 어렵게 만들지 않는다. 각 난이도에서도 20~30%는 이전의 쉬운 배치를 섞어 망각을 확인한다. 초기 쉬운 자세와 최종 임의 관절 자세는 초기화 분포가 다르므로, 최종 분포를 별도로 검증한다.

### 2단계: 운반·내려놓기·놓기

1단계 모델이 실제로 잡고 들어 올린 상태를 초기 상태로 사용한다. 시작과 목표 영역은 겹치지 않으며, 동일한 팔로 잡기·운반·놓기가 가능한 경로를 확인한다.

난이도별 목표 거리 후보는 **22~28 → 28~35 → 35~42 → 42~50 → 50~60cm**다. 이는 수정할 목표 범위이고, 현재 코드의 값이 아니다. 각 구간에서 초기화와 실제 운반·놓기 시험을 통과한 배치를 사용한다. 특히 28~42cm 구간을 포함한 모든 구간의 다양한 좌우 배치에서 성공은 아직 검증하지 못했으므로, 위 성공 사례만으로 전체 범위를 승인하지 않는다.

성공은 목표 내부에 내려놓고 로봇 접촉을 없앤 채 안정적으로 1초 유지하는 것이다. 초기화에 사용한 잡기 정책의 성공률과 재시도 횟수도 기록해, 쉬운 성공 배치만 남는 편향을 확인해야 한다.

### 3단계: 전체 작업·장애물·전달

이 단계부터 다시 잡지 않은 상태로 시작한다.

| 난이도 | 구성 | 통과 전에 필요한 물리 검증 |
|---|---|---|
| 0 | 1·2단계를 연결한 한 팔 전체 작업 | 열린 집게에서 시작해 실제로 잡고 놓기까지 완료 |
| 1 | 한 팔 작업에 랜덤 장애물 추가 | 팔과 물체 모두 장애물에 끼지 않는 경로 |
| 2 | 쉬운 전달 전용 배치 | 보내는 팔 잡기 → 받는 팔 안정적 잡기 → 보내는 팔 놓기 → 최종 놓기 |
| 3 | 전달 배치와 양팔 사용 선택을 다양화 | 필요한 공유 공간·물체 자세·충돌 없는 동작 확인. 동시 지지는 먼저 성공 사례를 확보 |
| 4 | 한 팔·장애물·전달 배치를 혼합 | 배치 종류별 성공률을 따로 측정 |

**현재는 전달 전용 배치를 학습 가능하다고 승인할 수 없다.** 먼저 정해진 쉬운 배치에서 실제 전달을 완주시킨 뒤 위치와 장애물을 넓혀야 한다. 검증용 제어기는 배치의 가능성 확인에만 사용하고, PPO 실행 중 팔 역할이나 동작을 대신 정하지 않는다.

### 4단계: 성공 유지·힘 절약

검증된 3단계 배치들을 유지하며 토크·집게 힘·두 팔 사용 비용의 계수를 **0 → 25 → 50 → 75 → 100%**로 올린다. 현재 비용의 증가 구조는 이 순서와 맞는다. 힘 비용 때문에 성공률이 하락하는지도 배치 종류별로 확인한다. 전달에 실제로 필요한 두 번째 팔까지 사용하지 못하게 만들지 않는다.

## 승급과 중단 기준

- 난이도 승급: 최소 10만 스텝 학습 후, 검증 50회에서 80% 이상을 두 번 연속 달성한다.
- 다음 단계 전환: 마지막 난이도를 통과하고, 승급용 검증과 다른 시드 100회에서 성공률 90% 이상을 확인한다. 1단계는 특히 2단계 초기화에 사용할 잡기 정책 자체를 검증한다.
- 스텝 예산 도달: 성공 조건을 못 통과했으면 저장 후 멈추고 진단한다. 실패한 채 다음 단계로 강제 전환하지 않는다.
- 진단: 총보상뿐 아니라 접근 거리 변화·잡기율·들기율·최종 성공률을 나눠 본다. 최근 검증 여러 회에서 잡기율이 0%면 단순히 스텝을 더 늘리기 전에 초기화와 탐색을 점검한다.
- 같은 모델 구조·관측·행동을 유지하고 가중치·옵티마이저·정규화 통계를 이어갈 수 있다. 이것이 새 단계에서 즉시 성공하거나 반드시 수렴한다는 뜻은 아니다.

## 이번 작업 범위

학습·보상·초기화·스케줄 소스와 실행 중인 학습은 변경하지 않았다. 관련 테스트와 별도 물리 시험만 수행했다. 확인된 문제를 반영한 실제 코드 수정과 새 방식의 학습 검증은 아직 남아 있다.
