# PPO 학습 기록

작성일: 2026-11-26 (한국 시간)

## 목표

두 팔 로봇이 5kg 물체를 잡아 장애물을 피해 목표 위치에 내려놓도록 학습한다. 혼자 처리할 수 있으면 한 팔을 사용하고, 필요한 경우 협동하거나 물체를 넘겨주도록 한다. 운반 성공을 우선하면서 실제 관절 토크와 집게 힘도 줄이는 것이 최종 목표다.

## 1. 처음 시도한 학습 방식

처음부터 물체 시작점·목표점과 장애물의 위치·크기가 무작위인 전체 과제를 PyTorch PPO로 학습하도록 했다. 위치를 보고 어느 팔을 사용할지 결정하는 규칙이나 운반 시연 없이, 하나의 정책이 두 팔을 모두 제어하는 방식이었다.

| 항목 | 초기 설정 |
|---|---|
| 물체 | 5kg, 길이 18cm |
| 관측 / 행동 | 관측값 89개 / 행동값 14개 |
| 행동 의미 | 각 구면 관절의 절대 회전 목표와 집게 열림 목표 |
| 제어 주기 | 0.02초 |
| 신경망 | Actor와 Critic 각각 256–256 MLP |
| PPO 수집 | 환경 8개 × 256스텝 = 업데이트당 2,048스텝 |
| PPO 업데이트 | 미니배치 256, 10 epochs, 학습률 0.0003 |
| 할인율 / GAE / clip | 0.999 / 0.95 / 0.2 |
| 에피소드 제한 | 2,000스텝, 시뮬레이션 시간 40초 |
| 검증 | 약 10만 스텝마다 별도 시드 50개 |

보상에는 접근·잡기·들기·운반·안착의 잠재함수 차이를 사용했다. 실제로 들어 옮긴 뒤 목표에 내려놓고 1초간 안정되면 성공 보너스 +100을 주었다. 처음부터 두 번째 팔 참여에 −10, 낙하에 −25를 적용하고, 실제 토크·집게 힘의 시간 적분과 충돌·소요 시간도 비용으로 넣었다.

### 실행 이력

| 실행 폴더 | 계획 | 마지막 저장 스텝 | PPO 업데이트 | 중단 경위 |
|---|---|---:|---:|---|
| `runs/ppo` | CPU, 총 1천만 스텝 | 200,704 | 98 | GPU 실행으로 전환하기 위해 사용자가 종료 |
| `runs/ppo_100m` | GPU에서 처음부터 총 1억 스텝 | 700,416 | 342 | 성과를 확인한 뒤 사용자 요청으로 중단하고 단계별 학습으로 전환 |

10만 스텝에서 로그와 창이 멈춘 것처럼 보인 현상은 검증 50개를 순차 실행하는 시간이었던 것으로 확인했다. 프로세스는 정상 동작했고 검증 후 학습이 재개됐다. 이후 평가 시작 안내와 진행률 로그를 추가했다.

## 3. 학습을 중단한 이유

물체를 잡는 기본 동작을 찾지 못한 상태에서 랜덤 배치·장애물 회피·운반·힘 최소화를 동시에 학습하고 있었다. 성공하지 못한 정책끼리 비교하면, 힘과 충돌 비용을 내며 움직이는 것보다 거의 정지하는 정책의 보상이 상대적으로 높게 나오는 상황을 확인했다.

가능한 원인으로는 접촉이 필요한 잡기를 처음부터 탐색하는 어려움, 절대 관절 목표에 탐색 노이즈가 더해지면서 생기는 급한 움직임, 성공을 배우기 전부터 힘과 두 번째 팔 사용을 억제한 점을 고려했다. 각 요인의 영향을 따로 비교하는 실험은 아직 하지 않았으므로 힘 비용 하나만이 원인이라고 단정하지는 않았다.

물리 검사에서는 한 팔로 5kg 물체를 들어 유지할 수 있었다. 따라서 물리적으로 가능한지와 PPO가 그 동작을 배웠는지를 구분했다. 횟수만 1억 스텝까지 늘려 기다리기보다 기본 동작부터 단계적으로 학습하도록 바꾸기로 했다.

사용자의 중단 요청에 따라 학습 프로세스에 인터럽트를 보내고, 현재 업데이트와 체크포인트 저장을 마친 뒤 정상 종료했다. 기존 학습 로그와 모델은 보존했다.

## 4. 변경한 학습 방식

새 커리큘럼은 하나의 모델로 다음 4단계를 이어서 학습한다.

| 단계 | 학습 내용 | 힘·두 번째 팔 비용 |
|---|---|---|
| 1 | 장애물 없는 좌우 대칭 기본 배치에서 잡고 들어 유지하기 | 없음 |
| 2 | 가까운 목표에 옮기고 놓기 | 없음 |
| 3 | 랜덤 시작점·목표점·장애물 배치의 비율 확대 | 없음 |
| 4 | 전체 랜덤 환경에서 성공을 유지하며 힘과 팔 사용 줄이기 | 0→100%로 강화 |

- 모든 단계에서 물체는 5kg, 관측값 105개와 행동값 14개를 공통으로 사용한다.
- 행동을 작은 관절·집게 목표의 증분으로 변경한다.
- 단계가 바뀌어도 모델 가중치·옵티마이저·관측 정규화를 유지한다.
- 현재 단계·난도·힘 비용 비율도 모델이 관측한다.
- 각 단계의 난도는 다섯 수준이다. 검증 성공률 80% 이상을 두 번 연속 달성하고 해당 수준에서 10만 스텝 이상 연습하면 다음 수준으로 넘어간다.
- 초기 단계에서는 열린 집게를 물체 가까이에 배치한다. 동작 중 자동 잡기·IK 제어·물체 부착은 사용하지 않는다.
- 사용하지 않는 빈 집게가 닫혀 있어도 물체의 안착 성공을 막지 않도록 성공 조건을 조정했다.

1단계 성공은 물체 바닥을 테이블에서 3cm 이상, 0.2초간 올린 뒤 잡은 채로 0.5초간 유지하는 것이다. 2~4단계에서는 들어 옮긴 뒤 목표 영역에 물체를 놓고 1초간 안정시켜야 한다.

관측·제어 방식이 바뀌므로 새 모델로 1단계부터 시작한다. 이후 1→2→3→4단계 사이에서는 모델을 초기화하지 않는다. 기존 89차원 관측·절대 목표 방식의 체크포인트를 새 방식에 직접 이어 붙이지 않는다.

## 5. 변경 후 확인한 내용과 현재 상태

- 자동 검사 18개를 통과했다.
- 새 1단계 초기 조건에서 양쪽 팔 모두 5kg 물체를 잡아 들 수 있음을 물리 검사로 확인했다. 이 검사는 학습된 PPO 정책의 성능이 아니다.
- 네 단계의 전환, 모델 초기화 없이 이어가기, 저장·재개·GPU 실행·보기 창을 확인했다. 단계 전환 검사는 테스트용 통과 기준을 사용했으며, 실제 학습으로 네 단계를 수료한 결과는 아니다.
- 짧은 4,096스텝 PPO 검증에서 완료된 4개 에피소드 중 2개에 안정적인 잡기 이력, 1개에 들어 올린 이력이 발생했다. 유지까지 포함한 1단계 성공 조건을 통과한 에피소드는 0개였다.
- 이 기록을 작성한 시점에는 4단계 방식의 본학습을 아직 시작하지 않았다.

본학습 시작 명령:

```bash
./run_curriculum.sh --total-steps 100000000 --device cuda --run-dir runs/curriculum_100m --viewer
```

1억 스텝은 네 단계 전체의 예산이다. 기준에 미달하면 해당 난도를 계속 연습한다. 마지막 평가는 중간 단계까지만 학습했더라도 4단계 전체 랜덤 과제에서 수행한다.

근거가 되는 기존 기록은 `runs/ppo_100m/config.json`, `metrics.csv`, `validation_*.json`, `latest.pt`에 남아 있다. 짧은 PPO 검증은 임시 폴더에서 수행했으며 본학습 성과와 구분한다.


## 6. 1단계만 1억 스텝 학습 시작

2026-11-26, 사용자 요청으로 1단계 전용 학습을 새로 시작했다.

- 실행 폴더: `runs/stage1_100m`
- 목표: 전체 환경 합계 100,000,000스텝, CUDA / RTX 3070
- 실행 옵션: `--curriculum --stage 1 --total-steps 100000000`
- 1단계의 다섯 난도는 성공률 기준으로 높이되, 2단계로 자동 전환하지 않도록 고정했다.
- 첫 100,352스텝 검증에서는 가장 쉬운 난도에서 50개 모두 성공했다. 이 결과는 랜덤 운반 전체 과제의 성공률이 아니다.
- 웹 홈에 실제 학습 환경 0번의 화면·스텝·난도·보상·검증 지표를 보내도록 연결했다. 녹화 영상 재생과 구분하며, 전송 시각과 연결 상태를 표시한다.
- 기존 단일 과제 정책의 상위 10개 영상은 `/replays.html`에 보존했다.
- 단계 고정 및 기존 기능 자동 검사 19개, 실시간 API 저장·조회와 데스크톱·모바일 화면을 검증했다.

학습은 별도 프로세스로 계속 진행하며 현재 업데이트마다 체크포인트를 저장한다. 로그는 `runs/stage1_100m/console.log`에서 확인한다. 실시간 전송이 끊겨도 학습은 계속하고 전송은 재시도한다.


## 7. 정기 녹화와 연속 실시간 영상 적용

2026-11-26, 1천만 스텝마다 로컬에 영상을 저장하고 웹 화면을 연속 영상으로 바꾸라는 요청을 반영했다.

- 14,776,320스텝에서 정상 저장 후 같은 모델·옵티마이저·정규화·환경·난수 상태를 복원해 재개했다.
- 1단계 고정과 전체 1억 스텝 목표를 유지했다.
- 최초 설정 시점에 지난 1천만 스텝 모델은 보존되어 있지 않아 소급 녹화하지 않았다. 대신 현재 모델을 `recordings/initial_014776320/`에 저장했다.
- 다음 2천만 스텝부터 1천만 간격으로 모델과 평가 영상 5개를 저장한다. 업데이트 수집 길이를 저장 경계에 맞춰 해당 스텝의 체크포인트를 남긴다.
- 저장 영상은 실제 물리 스텝마다 렌더링한 50fps MP4이며 1배속으로 재생한다. 실제 학습 중의 탐색 동작과 구분해 메타데이터에 `checkpoint_evaluation`으로 표시한다.
- 현재 모델의 첫 저장 영상은 269프레임, 5.38초이며 5개 평가 에피소드 모두 1단계 성공이었다.
- 웹은 1초마다 정지 화면을 바꾸는 방식에서 연속 영상 중계로 변경했다. 진행 지표의 1초 갱신은 유지한다.
- 연속 영상 소스는 인증을 요구하고, 외부 시청은 기존 본인 계정 전용 웹페이지를 통한다. 관측 중일 때만 렌더링 빈도를 높여 학습 부하를 줄인다.
- 검사용 32·64스텝 경계에서 정확한 체크포인트 저장과 50fps 영상 생성을 확인했다. 연속 영상의 외부 수신과 모바일 화면도 확인했다.


## 8. 단계별 2천만 스텝과 500만 간격 녹화로 변경

2026-11-26, 사용자 요청으로 1단계 예산을 1억에서 2천만 스텝으로 줄이고, 같은 모델로 2단계를 추가 2천만 스텝 학습하도록 변경했다.

- 기존 학습을 취소하거나 초기화하지 않고, 15,577,088스텝에서 정상 저장 후 CUDA 학습을 재개했다. 실행 폴더는 `runs/stage1_100m`을 유지한다.
- 1단계는 누적 20,000,000스텝에서 마친다. 최종 평가와 `stage1_final.pt` 저장 후, 그 시점의 정책·옵티마이저·정규화 상태를 유지해 2단계로 자동 전환한다. 최고 점수 과거 모델로 되돌리지 않는다.
- 2단계는 가까운 목표로 옮겨 집게를 열고 내려놓는 과제이며, 추가 20,000,000스텝을 사용해 누적 40,000,000스텝에서 종료한다. 성공률에 따라 단계 안의 난도만 높이고 3단계로 자동 전환하지 않는다.
- 전환 직후 `stage2_initial.pt`, 전환 이력 `stage_handoffs.jsonl`을 남긴다. 전환 경계에서 중단되더라도 체크포인트에 저장된 일정으로 재개할 수 있다.
- 영상 간격을 5,000,000스텝으로 바꿨다. 이미 1,500만 스텝을 지난 상태이므로 다음 정기 저장은 누적 2천만·2,500만·3천만·3,500만·4천만 스텝이다. 2천만 영상은 전환 전 1단계 모델이다. 50fps·평가 5개·별도 인코딩은 유지한다.
- 웹 화면은 실제 현재 단계에 맞춰 제목·성공 조건·성공률 표시가 바뀌며, 현재 단계의 진행률과 전체 누적 스텝을 함께 표시한다.
- 자동 검사 21개를 통과했다. 짧은 실제 PPO 실행에서 정확한 단계 경계와 전환 시 정책·옵티마이저·정규화·난수 상태의 일치를 확인했고, 경계 체크포인트에서의 재개도 검증했다. 실제 본학습이 2천만 스텝에 도달했다는 의미는 아니다.

변경 후에도 채팅에 정기 학습 로그를 올리지 않고 로컬 로그와 웹에서 진행 상태를 확인한다.


## 9. 현재 커리큘럼 정책의 보상 상위 10개 공개

2026-11-26, 현재 정책의 상위 10개도 웹에서 볼 수 있도록 추가했다.

- 학습을 중단하지 않고 17,160,192스텝의 `latest.pt`를 별도 폴더 `runs/stage1_100m/web_replays/step_017160192/`에 고정했다. 이전 단일 과제의 최고 정책과 구분한다.
- 고정된 1단계·최고 난도 정책을 CPU에서 평가 시드 1,004,040,000부터 50회 실행했다. 잡고 들어 유지하기 성공률은 50/50이었다. 목표에 운반·내려놓기 전체 과제의 성공률은 아니다.
- 누적 보상 순으로 상위 10개를 선택하고, 같은 시드로 다시 실행한 실제 MuJoCo 영상을 각각 50fps로 저장했다. 선택된 영상의 보상은 모두 약 92.370392였다. 1단계는 좌우 기본 배치이므로 여러 시드가 같은 배치와 동작으로 이어질 수 있음을 화면에 표시했다.
- `/replays.html`에서 새 상위 10개를 선택·재생할 수 있으며, 이전 단일 과제 정책의 영상은 `/previous-replays.html`에 보존한다. 홈에서 새 페이지로 이동할 수 있다.
- 영상의 정책 스텝·단계·생성 시각을 표시한다. 저장 시점의 평가 영상이며 계속 학습 중인 최신 모델로 자동 갱신되는 영상은 아니다.
- 1단계 성공은 ‘잡고 들기 성공’으로 표시하고, 물체의 최대 상승 높이를 보여준다. 2초보다 짧은 영상에서도 미리보기가 생성되도록 내보내기를 수정했다.
- 10개 영상 모두 평가 순위·시드·보상·모델 해시가 일치하고 50fps인지 확인했다. 브라우저에서 10개 선택과 재생, 이전 정책 페이지, 390px·320px 화면을 확인했다. 학습과 실시간 영상 전송은 계속 유지했다.


## 10. 절전 복귀 후 GPU 오류로 중단

2026-11-26 13:01 KST에 학습 상태를 확인했다. 마지막 완료된 체크포인트는 19,750,912스텝, 1단계 최고 난도이며 2단계로 전환하기 전이다.

- 12:51:58 절전 진입, 12:58:16 복귀 직후 커널에 NVIDIA GPU 메모리 오류가 기록됐다. 학습 프로세스는 `CUDA error: unspecified launch failure`로 종료됐다.
- 커널은 UVM의 전역 치명 오류와 `Node Reboot Required`를 기록했다. 새 Python 프로세스에서도 CUDA 초기화가 실패했으므로 GPU 학습을 재개하지 않았다.
- `latest.pt`를 CPU에서 정상적으로 열어 모델·옵티마이저·커리큘럼 상태와 19,750,912스텝을 확인했다. 단계별 2천만/추가 2천만 일정은 유지돼 있다.
- 종료 처리에서 웹 상태가 `finished`로 표시됐지만 실제 정상 완료가 아니다. 현재 학습 프로세스는 실행 중이 아니다. PC 재부팅 후 마지막 체크포인트에서 이어서 실행해야 한다.


## 11. Conda 전용 실행과 웹 연결 복구 준비

2026-11-26, 사용자 요청으로 `dual-reacher` Conda 환경(Python 3.10)을 설치하고 실행 스크립트를 활성화된 Conda Python을 사용하도록 바꿨다. PyTorch 2.5.1+cu124의 GPU 연산과 기존 자동 검사 21개 통과를 확인했다.

로컬 재개 명령에는 웹 전송 옵션이 빠져 있었고 재부팅으로 터널도 종료돼 Sites에 이전 1단계 화면이 남아 있었다. 현재 사용자 프로세스는 2천만 스텝에서 2단계로 자동 전환해 학습 중임을 확인했다. 새 터널과 인증 정보를 메모리로 전달하는 로컬 연결 준비 프로세스를 마련했다. `run_web_training.sh`로 사용자 본인이 재개하면 로컬 창과 웹을 함께 연결한다. 기존 사용자 학습 프로세스는 중단하거나 다시 실행하지 않았다.

웹 영상 연결이 실패하면 최근 수신한 정지 화면을 표시하고 연속 영상 재연결을 시도하도록 변경했다. 학습 오류를 정상 완료로 표시하던 종료 상태도 수정했다. README에 실제 사이트 주소와 Conda 및 웹 실행 명령을 추가했다.
