# 추가 연구 계획

현재 GPU 실행 목표는 **두 팔 로봇 1세트가 있는 시뮬레이션 1개**에서 학습하는 것이다. **추가 연구 1번은 독립된 시뮬레이션 여러 개를 만드는 확장**이다. 시뮬레이션 화면에 보이는 개수와 실제 병렬 학습 환경 개수는 구분한다.

## 1. 여러 시뮬레이션에서 다른 시나리오를 동시에 학습하기

두 팔 로봇·물체·목표·장애물로 구성된 환경을 여러 개 복제하고, 각 환경에서 다른 시나리오를 동시에 실행한다. **하나의 PPO 정책**이 모든 환경의 경험을 모아 학습한다. 로봇을 한 공간에 계속 추가하는 방식이 아니라, 서로 충돌하지 않는 독립된 시뮬레이션을 여러 개 운영한다.

- 시작점·목표점·장애물의 위치와 크기, 난수 시드를 환경마다 다르게 설정한다.
- 한 팔 운반·양팔 협동·물체 넘겨주기가 필요한 배치를 포함하되, 사용할 전략은 정책이 결정한다.
- 물체 무게 1kg, 관측 105개·행동 14개, 보상 버전과 물리 설정은 동일하게 유지한다.
- 병렬 환경 수를 1·8·32·64 등으로 늘려 처리 속도, 메모리와 성공률을 비교한다. GPU 물리를 사용할 때는 실제 측정에 따라 가능한 환경 수를 정한다.
- 화면은 대표 환경 1개를 표시하고, 다른 환경은 화면 없이 경험을 수집할 수 있게 한다.

학습 예산은 모든 환경에서 수집한 **전체 스텝의 합**으로 맞춘다. 예를 들어 환경 8개를 각각 1스텝 진행하면 총 8스텝이다. 환경 수를 바꿀 때는 PPO 업데이트당 전체 샘플 수와 배치 설정도 함께 기록해 병렬화 효과와 학습 설정 효과를 구분한다.

평가는 학습에 사용하지 않은 같은 시나리오 목록에서 진행한다. 성공률, 성공까지 걸린 시간, 팔 사용 수, 토크·집게 힘 사용량, 충돌, 시나리오별 성능을 확인한다. 같은 스텝 예산에서의 성능과 실제 학습에 걸린 시간을 모두 비교한다.

## 2. 동일한 환경에서 여러 신경망을 학습해 비교하기

PPO 알고리즘은 고정하고 **정책·가치 신경망의 구조**를 바꿔 비교한다. 네트워크 구조의 효과를 먼저 비교하며, PPO·SAC 등 알고리즘 자체의 비교는 별도 실험으로 구분한다.

| 후보 | 구조 예시 | 확인할 점 |
|---|---|---|
| 기준 MLP | 현재 구조: 은닉층 256 → 256, Tanh | 비교 기준 |
| 작은 MLP | 128 → 128 | 적은 파라미터로도 성공 가능한지 |
| 깊은 MLP | 256 → 256 → 256 | 추가 깊이가 협동·운반 학습에 도움이 되는지 |
| 큰 MLP | 512 → 512 | 표현력 증가와 학습 시간·메모리의 관계 |
| 순환 신경망(추가 실험) | MLP + GRU/LSTM | 접촉·이동 이력을 기억하면 도움이 되는지 |

각 후보는 같은 관측·행동 차원, 물리 엔진·버전, 보상 버전, 단계·난도 일정, 환경 수, 전체 학습 스텝, 평가 시나리오를 사용한다. MLP 비교는 동일한 PPO 설정으로 먼저 수행하고, 모델별 조정이 필요하면 별도 실험으로 기록한다. 순환 신경망은 시퀀스 수집·은닉 상태 초기화 등 학습 코드 변경이 필요하므로 MLP 결과와 구분한다.

각 구조는 독립적인 초기 가중치로 학습하며 최소 3개 시드에서 반복한다. 1단계부터 이어가는 실험이라면 구조마다 자체 1단계 모델을 학습한 뒤 2단계로 넘긴다. 형태가 다른 신경망에 기존 MLP 가중치를 그대로 넣어 비교하지 않는다. 모델 선택용 검증 시나리오와 최종 성능을 보고할 테스트 시나리오도 분리한다.

| 비교 지표 | 기록 방법 |
|---|---|
| 과제 성공률 | 전체·시나리오별 성공률의 시드 평균과 편차 |
| 학습 효율 | 목표 성공률에 도달한 전체 스텝과 실제 시간 |
| 운반 품질 | 안착률, 충돌, 목표 밖 잡기 손실, 성공 소요 시간 |
| 힘 사용 | 성공 에피소드의 관절 토크·집게 힘 누적량 |
| 협동 방식 | 한 팔·두 팔 사용 비율과 넘겨주기 사례 |
| 계산 비용 | 파라미터 수, GPU 메모리, 학습·추론 속도 |

결과는 `runs/studies/<실험명>/<모델명>/seed_<번호>/`처럼 분리해 모델·설정·로그·평가 영상을 보관한다. 평균 보상은 성공률과 함께 해석하며 보상 버전이나 물리 설정이 다른 실험의 점수를 직접 비교하지 않는다.

## 3. PPO·A2C·SAC 독립 비교

`start_three_models.sh`는 모델별로 시뮬레이션 하나를 사용합니다. 세 알고리즘 모두 연속 행동 14개이고, 동일한 1kg 물리 환경과 새 보상 v3를 사용합니다. DQN은 제외했습니다.

각 프로세스가 별도의 커리큘럼 상태를 저장합니다. 같은 난도에서 검증 성공률 80% 이상을 두 번 연속 달성하고 최소 10만 스텝을 연습하면 **그 모델만** 다음 난도로 올라갑니다. 다른 모델은 자신의 조건을 통과해야 합니다. 예산은 각 2천만 스텝이며, 예산 도달로 다음 단계에 강제 전환하지 않습니다.

초기화 시드와 검증 시나리오의 규칙은 같지만, 행동·에피소드 길이·업데이트·현재 난도는 독립적입니다. 서로 다른 난도에서 측정한 보상을 같은 조건의 비교로 해석하지 않습니다. 하나가 오류가 나거나 예산을 완료해도 다른 모델의 학습은 계속됩니다.

기존 Sites 웹 주소의 모델 선택기에서 실시간 화면·진행도·에피소드 표·그래프·각 모델의 평가 상위 10개를 확인합니다. 500만 스텝마다 50fps 평가 영상을 저장하고, 학습 중/종료 후 PNG·SVG·CSV와 발표 자료를 모델별 폴더에 남깁니다. 저장 구조와 실행·재개 명령은 README에 있습니다.

PPO·A2C는 정책·가치망, SAC는 정책·쌍 Q망 등 알고리즘에 필요한 구조가 다릅니다. 기본 은닉층은 256→256이며 같은 물리·행동 조건에서 비교합니다. 모델 초기 가중치·옵티마이저·정규화·SAC 버퍼는 공유하지 않습니다.

이번 시작 범위는 세 모델의 1단계 접근·잡기·들기입니다. 양팔 전달 배치의 물리적 완주와 후속 단계별 시나리오 교육과정은 별도 검증이 필요합니다. 초기 동작 시험과 웹 연결 시험의 성공을 강화학습 수렴으로 표현하지 않습니다.
